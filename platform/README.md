# Rails platform

Ruby 3.4, Rails 8.1, PostgreSQL, and Hotwire. Run commands from this directory
unless using the root Docker Compose setup.

See [development setup](../docs/development.md) for prerequisites and commands.

Current routes:

- `/`: public scaffold status page.
- `/up`: application liveness; does not check PostgreSQL or Samba readiness.

The model layer implements the README identity foundation: organizations, employees,
groups, dashboard roles, devices and public credentials, enrollment tokens, versioned
policies, delivery status, elevation requests and grants, provisioning operations,
and audit events. Local dashboard users have session, MFA, and passkey records.
Authentication flows, agent APIs, directory writes, and permission enforcement
remain unimplemented. Add authentication and authorization
before administrative features. Select a durable Active Job adapter before
provisioning work; the current async adapter is for development only.


Run `bundle exec ruby bin/rails db:prepare` after installing dependencies. The
new migration extends the scaffold users table; existing scaffold rows must be
populated with real email, name, and password digest values before migrating.
It intentionally does not invent credentials for existing accounts.

Employees represent directory identities; User passwords are only for local
application authentication. Never store directory passwords, device private
keys, raw session tokens, or raw enrollment tokens in these records. Token digest
creation and verification belong to the authentication/enrollment service. MFA
secrets use Active Record encryption and require deployment encryption keys.

Organization-scoped relationships reject records from another organization.
Controllers must still authorize and scope every query. Roles store explicit
permission mappings; they do not grant Windows privileges. Company and audit_logs
associations on User remain aliases for Organization and AuditEvent.

Policy revisions and audit events reject model updates and destruction. Database
foreign keys protect historical references; production audit retention still needs
restricted database permissions and external export. Direct SQL and bulk writes
bypass model validation and immutability callbacks. Store only sanitized metadata
and provisioning results; these JSON fields do not automatically redact secrets.

Elevation records track desired and reported state separately. Approval and grant
creation require an authorized service transaction; records alone do not enforce
Windows permissions or expire privileges. EnrollmentToken#consume! uses a row lock;
call it within the same transaction as enrollment. No raw token is generated by
this model.
